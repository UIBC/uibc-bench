# 测试台怎么保存（三层，缺一层就会丢或变味）

## 第一层：版本化（已做，本机）

测试台自己是一个 git 仓，只跟踪“能复跑的部分”（`harness/`、`bench.py`、`cases/`、`baseline.json`、
`results.schema.json`、`*.ps1`），不跟踪被测仓库、证书、历史运行产物、`dist/`。

```
tag v0.1.0  97 用例首次基线
tag v0.1.1  run/report/diff/issues/trend/verify-results 全自测通过
tag v0.1.2  保存/分发/差距三份文档入档
tag v0.2.0  118 用例：+F 性能阈值组 +G 包对抗边界组 +规范对照调研
tag v0.2.1  开箱即用修正：包内带顶层目录、缺仓库整组报 BLOCKED
```

为什么必须版本化：判定口径会变（例如“应 400 却返回 200 才算 FAIL”），**口径变化本身要留痕**，
否则半年后没人说得清“当时为什么判失败”。

## 第二层：可搬运（已做，本机）

| 产物 | 位置 | 用途 |
|---|---|---|
| `dist\uibc-bench-v0.2.1.bundle` | 单文件 git bundle（含全部历史与 tag） | 任何机器 `git clone bundle 目录` 即得完整测试台含历史 |
| `dist\uibc-实测台-0.2.1-20261123.zip` + `.sha256` | 分发包 81KB，sha256 `bc84cc09…` | 给同事/合作方，解压（含顶层目录）→ `setup.ps1` → `run_all.ps1` |
| `runs\trend.html` | 跨运行趋势 | 证明“在变好还是变坏” |
| `cases\使用手册_给别人用.md` | 使用/判定/贡献/红线 | 让外部人不用问就能用，这就是“基础设施化”的最小件 |

bundle 的优势：一个文件，不怕目录被清理；clone 出来版本号、tag、提交历史都在。

## 第三层：异机归档（未做，本机做不了 → 需回家机）

这台公司机没有 F 盘、也没有 `D:\Workbuddy`，所以“进家底盘点”和“登记 WeKnora”两步**必须回家机执行**。
回家机上的动作（三条命令，或在资源管理器里复制）：

```powershell
# 1) 归档到 家底盘点
$dst = 'F:\家底盘点\生态规划\发布\uibc-实测台'
New-Item -ItemType Directory -Force -Path $dst
Copy-Item -Recurse -Force 'C:\Users\SZYL\Doubao\uibc-实测台\*' $dst
Copy-Item 'C:\Users\SZYL\Doubao\uibc-实测台\dist\*' $dst\dist -Force

# 2) 校验一份哈希，证明两边一致
Get-FileHash "$dst\dist\uibc-实测台-0.1-20261123.zip" -Algorithm SHA256

# 3) 登记 WeKnora（按既有约定：先 SSOT 一致化再入库）
#    入库对象：cases\场景清单.md、cases\发现清单_20261123.md、README.md
#    并在 weknora_sync_state.json 里做双向确认
```

家机上的路径如果与上面不同，改 `$dst` 即可；`uibc-core-public\`（被测仓库）不必复制，`setup.ps1` 会重新克隆。

## 日常维护节奏（建议）

| 时机 | 动作 |
|---|---|
| 每次改代码/改判定 | `git commit` + 说明为什么改判据；必要时 `git tag` |
| 每次跑完 | `.\run_all.ps1`（自动出 `summary.html`）；确认无回归再 `-UpdateBaseline` |
| 每周 | `python bench.py trend` 看趋势；把新增 FAIL 登记进 `cases\发现清单` |
| 每月 | 重打 `bundle` + zip，覆盖异机归档；清 `runs\` 里只保留带标签的运行 |
| 换机/换人 | 只给 `bundle` 或 zip；不要给整个目录（含证书与私钥材料） |

## 三条不可破的规矩

1. **不删 FAIL 让结果变绿**：`compare_baseline.py` 会把“用例消失”单独报出来。
2. **不放宽判据不写理由**：判据变化要写进 `cases\场景清单.md`。
3. **分发不带证书与密钥**：`_pki\`、`.venv\`、`_logs\` 一律不进包。
