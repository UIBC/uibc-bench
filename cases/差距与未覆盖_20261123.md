# 差距与未覆盖（自查，不是给自己发奖）

直接回答“是不是做到最好了”：**不是**。目前是“Windows 单机可复跑、有基线、能分发”的水平，
够当团队基础设施的雏形，但离“任何人任何环境都能复跑、结果被独立第三方认可”还差六块。

## 一、六块硬缺口（按影响排序）

| # | 缺口 | 现在是什么样 | 为什么算缺口 | 补法（成本） |
|---|---|---|---|---|
| G1 | **只有 Windows 一种系统实跑** | 1086 条单测、CLI、并发锁都在 Windows 跑通；Linux/macOS 一次没跑 | 服务器与海外合作方基本是 Linux；Windows 独有的 `msvcrt` 锁分支能过，不代表 `fcntl` 分支也过 | GitHub Actions 加 `ubuntu-latest` + `macos-latest` 两个 job，同一套 `bench.py`（半天） |
| G2 | **没有 CI，靠人记得跑** | 现在只有 `run_all.ps1` 手动跑 | “能不能跑”取决于人有没有跑，等于没有守门 | 把 `bench.py run --only s05,s03` 挂 pre-push hook，全量挂 nightly（1 天） |
| G3 | **结果没有外部独立评审** | 97 条判定全是我自己写、自己判 | 自查自证；按既有门禁，外发前须 LGD-Eval 独立评测 + Muse 终审 | 把 `受审材料` 与 `runs\` 交给 LGD-Eval 复跑；它跑出的差异才是真结论（需要评测号凭据） |
| G4 | **平台侧只读，写链路未测** | 注册/审批/上架/撤销一条没跑 | 上线后真正会出事的是写链路（重复注册、审批卡住、撤销未生效） | 需要一个测试租户或沙箱环境；无凭据前只能标 BLOCKED（需对方配合） |
| G5 | **没有性能基线，只有单点观测** | 延迟、内存、并发都是“测到一次的数” | 没有阈值就没有告警：下次慢了 3 倍，报告里看不出来 | 给关键用例加阈值（如 agents P95 < 300ms、did 解析 < 200ms），超阈值判 WARN（1 天） |
| G6 | **用例覆盖仍不完整** | 97 条，矩阵里还有 20+ 项 `待测`／`受限` | 撤销/迁移链、`k1_` secp256k1、重放、签名降级、多供方并发、跨机构互认都没测 | 按 `cases\场景清单.md` 逐条补，优先补“上线后必然遇到”的（1–2 周） |

## 二、已经做到的部分（可以拿出来说的）

- 用例固定、可枚举、可复跑：97 条，分 5 组，跑一次 ~5 分钟（含全量单测）。
- 结果有契约（`results.schema.json`），能被机器校验；`verify-results` 实测 91 条 0 问题。
- 有基线、有回归检测、有“用例消失”报警，能防止“删用例让结果变绿”。
- 有跨运行趋势页（`runs\trend.html`），能看出同一用例的历史变化。
- 有分发形态（bundle + zip + sha256），换机不用重搭。
- 平台侧探测保持只读、并发 ≤8、不注册不写入——这条红线写在脚本注释里。

## 三、判断“够不够好”的三条硬标准

1. **一个没参与的人，能不能在半小时内复跑出同样结论？**
   现在：能（给 zip/bundle，`setup.ps1` + `run_all.ps1`）。这是及格线，已过。
2. **结论能不能被第三方独立推翻或确认？**
   现在：不能——只有我的判定。这是 G3，未过。
3. **环境换了（Linux/Py3.10/无 Docker）结论还成立吗？**
   现在：不知道。这是 G1/G2，未过。

三条里过了一条半。所以答案是：**雏形合格，基础设施不合格。**

## 四、如果只做三件事，先做这三件

1. **CI 上 Linux**（G1+G2 一起解）：一个 workflow，两个 job，跑 `s05,s03,s04`。
   理由：这条最能证明“不是只在我这台机器上能跑”。
2. **外部独立复跑**（G3）：把 bundle 给 LGD-Eval，让它用自己的环境跑一遍，比对 `baseline.json`。
   理由：这是外发门禁要求，也是唯一能证明“判据不是我自说自话”的办法。
3. **阈值化**（G5）：先给 3 个关键用例加数值阈值，让“变慢”也能报警。
   理由：成本最低，立刻让报告从“快照”变成“监控”。
